# 태국어 FLEX 학습 서비스 통합 기획 설계

- 작성일: 2026-07-16
- 상태: 기능 기획 승인 완료, 통합 문서 검토 대기
- 대상: 인프라, ERD, 백엔드, 프론트엔드 설계의 공통 기준
- 관련 문서: [`docs/flex-problem-type.md`](../../flex-problem-type.md)

## 1. 문서 목적

이 문서는 태국어 어휘 학습과 FLEX 읽기·듣기 문제 풀이를 결합한 서비스의 제품 요구사항을 정의한다. 이후 단계에서 기술 선택이나 화면 세부 디자인이 달라져도 이 문서의 사용자 경험과 도메인 규칙은 유지한다.

후속 기획 세션은 다음 순서로 진행한다.

1. 현재 세션: 서비스 기능 기획 확정과 문서화
2. 다음 세션: 인프라 설계와 프로젝트 아키텍처 브레인스토밍
3. 그다음 세션: 백엔드 구현 계획 브레인스토밍
4. 그다음 세션: 프론트엔드 구현 계획 브레인스토밍

이 문서는 첫 번째 세션의 완료 기준이며 개발 계획이나 구현을 포함하지 않는다. DB, 검색 엔진, 저장소, 작업 큐, AI·TTS 공급자 같은 기술은 다음 인프라 설계 세션에서 정한다.

## 2. 제품 목표와 핵심 원칙

### 2.1 제품 목표

사용자가 태국어 어휘의 표기, 의미, 한국어 발음, 성조, 음성을 즉시 확인하면서 FLEX 읽기·듣기 문제를 학습하도록 돕는다.

초기에는 서비스 소유자가 주 사용자이지만, 한국외국어대학교 구성원 가입과 외부 검수 전문가 참여를 지원할 수 있어야 한다.

### 2.2 핵심 원칙

1. **어휘가 중심이다.** 문제, 지문, 문장, 보기, 해설은 모두 공용 어휘 데이터와 연결된다.
2. **피드백은 즉각적이다.** 태국어를 보는 자리에서 의미·발음·성조·음성을 확인한다.
3. **학습 중 AI를 호출하지 않는다.** 학습 콘텐츠와 음성은 사전에 생성·검수·저장한다.
4. **AI 결과를 바로 게시하지 않는다.** 중복 검사, 교차 검증, 필요 시 전문가 검수, TTS 준비를 거친다.
5. **관리자는 태국어를 모른다.** 관리 기능은 관리자의 언어 직관이 아니라 검증 결과와 근거를 중심으로 구성한다.
6. **초기 범위를 단순하게 유지한다.** 숙련도, 모의고사, 시험 모드처럼 현재 학습에 필수적이지 않은 기능은 제외한다.

## 3. 초기 범위

### 3.1 포함 기능

- 한국외국어대학교 이메일 기반 회원가입·로그인
- 홈 추천과 신규 콘텐츠 안내
- 읽기·듣기 문제 목록 및 풀이
- 모든 학습용 태국어의 단어·표현·문장 피드백
- 공용 어휘 검색과 상세 정보
- 여러 개의 개인 단어장
- 문제 저장과 오답 문제 필터
- 단어 연습
- 태국 문자·발음 및 문법 개념 학습
- 콘텐츠 오류 신고
- 관리자 AI 어휘·문제 생성
- 어휘 중복 방지와 병합
- AI 교차 검증과 전문가 검수 정책
- TTS 일괄 생성과 개별 재시도
- 검수·게시·숨김·버전·변경 기록
- 문제·어휘 추천을 위한 원시 학습 기록

### 3.2 초기 범위에서 제외

- 합격 루틴, 스트릭, 일일 목표
- 시험 모드와 모의고사
- 어휘 숙련도 점수·등급·백분율
- `나의 학습` 전용 메뉴와 통계 대시보드
- 집계형 사용자 학습 통계 테이블
- 태국 문자 암기 퀴즈와 개념 학습 진도
- 문제 풀이 중 힌트 사용 여부 기록
- 단어 호버, 문장 확인, 음성 재생, 듣기 대본 공개 여부 기록
- PDF·이미지 자료 관리 페이지
- 문서·페이지별 처리 상태와 부분 실패 UI
- 원본 페이지 썸네일·미리보기
- 페이지별 요약·추출 결과·신뢰도·재분석
- 파생 콘텐츠의 원본 문서·페이지 출처 추적
- 외부 전용 검색 엔진 도입 확정
- 구체적인 UI 색상·간격·컴포넌트 배치

## 4. 사용자와 권한

### 4.1 역할

| 역할 | 주요 권한 |
| --- | --- |
| 일반 사용자 | 문제 풀이, 어휘 검색, 단어장, 저장, 단어 연습, 오류 신고 |
| 관리자 | 콘텐츠 생성·수정·검수·게시·숨김, TTS, 설정, 사용자·전문가 관리, 감사 기록 확인 |
| 검수 전문가 | 초대받은 콘텐츠의 직접 수정과 승인, 검수 의견 작성 |

관리자와 검수 전문가는 일반 학습 기능도 사용할 수 있다. 같은 계정에서 역할에 따라 관리자 또는 검수 화면으로 전환한다.

### 4.2 일반 사용자 인증

- 일반 가입은 학교 이메일 도메인으로 인증 가능한 모든 사람에게 허용한다.
- 초기 허용 범위는 한국외국어대학교 학교 이메일이다.
- 비밀번호 없이 이메일 인증으로 가입과 로그인을 통합한다.
- 이메일에는 로그인 링크와 6자리 인증 코드를 함께 제공한다.
- 링크 도착 화면에서 사용자가 확인 버튼을 눌러야 세션을 생성한다. 이메일 보안 스캐너가 링크를 미리 방문해도 로그인되지 않아야 한다.
- 처음 인증한 허용 이메일은 계정을 생성하고, 기존 계정은 로그인한다.
- 정확한 허용 도메인, 코드·링크 만료 시간, 재전송 제한, 세션 방식은 인프라·백엔드 단계에서 정한다.

### 4.3 검수 전문가 인증

- 전문가는 관리자의 초대를 통해서만 가입한다.
- 전문가는 학교 이메일이 아닌 외부 이메일을 사용할 수 있다.
- 초대 대상 이메일과 실제 인증 이메일이 일치해야 한다.

### 4.4 관리자 추가 인증

- AI 콘텐츠 생성과 같은 민감한 관리자 작업에는 휴대폰 OTP를 요구한다.
- OTP 공급자, 유효 시간, 재인증 주기는 인프라·백엔드 단계에서 정한다.
- 관리자와 전문가의 모든 콘텐츠 변경·승인 작업은 감사 기록에 남긴다.

## 5. 공통 태국어 상호작용

### 5.1 적용 범위

문제 설명, 지문, 대화, 질문, 보기, 해설, 어휘 예문, 개념 학습 예시 등 학습 콘텐츠에 표시되는 모든 태국어에 같은 상호작용 원칙을 적용한다.

태국어 텍스트는 의미 있는 어휘 단위로 분할한다. 기능어, 조사에 해당하는 표현, 전치 기능 표현 등도 제외하지 않는다.

### 5.2 단어·표현 피드백

데스크톱에서는 다음 동작을 제공한다.

- 단어 호버: 문맥에 맞는 한국어 뜻, 한국어 발음, 성조 기호 표시
- 단어 클릭: 해당 발음의 단어 음성 재생
- 다단어 표현 배지 호버: 표현 전체의 뜻, 한국어 발음, 성조 기호 표시
- 다단어 표현 배지 클릭: 표현 전체 음성 재생

모바일에서는 호버를 사용할 수 없으므로 태국어 단어 또는 표현을 탭하면 정보 표시와 음성 재생을 함께 실행한다.

성조는 `-`, `\`, `^`, `/`, `∨` 같은 기호만 사용자에게 표시한다. `하강 성조` 같은 성조 이름은 기본 학습 피드백에 표시하지 않는다.

### 5.3 문장 피드백

- 문장은 자연스러운 문단 흐름을 유지한다.
- 모든 문장을 한 줄에 하나씩 강제로 배치하지 않는다.
- 문장 끝 또는 문장과 연결된 위치에 번호 배지를 표시한다.
- 문제 화면에는 문장 번호를 찾기 쉬운 별도 목록을 제공할 수 있다.
- 문장 번호 호버: 문장 전체 해석, 한국어 발음, 성조 기호 표시
- 문장 번호 클릭: 문장 전체 음성 재생
- 모바일 탭: 문장 정보 표시와 음성 재생
- 대화문은 화자별 줄 구분을 유지한다.
- 질문과 보기는 각각 독립된 문장 행 또는 블록으로 취급한다.

### 5.4 다단어 표현

- 어휘 항목은 `WORD` 또는 `EXPRESSION` 종류를 가진다.
- 표현도 검색, 저장, 단어장 추가, 연습, 유의·반의·관련 관계 설정 대상이다.
- 표현 안의 각 단어는 계속 개별 호버·클릭 대상이다.
- 표현 전체에는 별도 배지를 제공한다.
- 겹치는 표현이 여러 개이면 초기에는 한 구간에 대표 표현 하나만 표시한다.

### 5.5 기록하지 않는 상호작용

다음 행동은 학습 기록이나 추천 입력으로 저장하지 않는다.

- 단어 호버
- 단어·표현 음성 재생
- 문장 주석 확인
- 문장 음성 재생
- 듣기 대본 공개

## 6. 어휘 도메인

### 6.1 어휘 항목

공용 어휘는 하나의 정규화된 태국어 표기당 하나의 어휘 항목을 사용한다.

어휘 항목의 개념적 책임은 다음과 같다.

- 태국어 대표 표기
- 검색·중복 판정을 위한 정규화 표기
- `WORD` 또는 `EXPRESSION` 종류
- 공개·숨김·보관 상태
- 생성 및 변경 이력

표시용 원문과 검색용 정규화 표기는 분리한다. 구체적인 정규화 방식과 DB 제약은 인프라·ERD 단계에서 정하되, 같은 정규화 표기의 중복 저장은 반드시 방지한다.

### 6.2 뜻

하나의 태국어 표기에 여러 뜻이 있을 수 있으므로 뜻을 별도 단위로 관리한다.

뜻 단위에 연결되는 정보는 다음과 같다.

- 한국어 뜻
- 품사
- 난이도
- 주제·분류
- 문맥 설명
- 유의어
- 반의어
- 관련어

동일 표기의 새로운 뜻을 발견하면 새 어휘 항목을 만들지 않고 기존 어휘 아래에 뜻 후보를 추가한다.

### 6.3 발음과 음성

- 하나의 어휘는 여러 발음을 가질 수 있다.
- 뜻은 해당되는 발음과 연결된다.
- 한국어 발음과 성조 기호는 발음 정보에 포함한다.
- 단어 음성은 발음 정보에 연결한다.
- 발음이 다르다는 이유만으로 같은 표기의 어휘를 복제하지 않는다.
- 같은 발음의 기존 음성 자산은 재사용한다.

### 6.4 어휘 관계

- 유의어, 반의어, 관련어는 뜻과 뜻 사이의 관계로 관리한다.
- 같은 표기라도 뜻이 다르면 관계가 달라질 수 있다.
- 관계에는 관계 종류, 방향, 검수 상태, 변경 이력을 둔다.

### 6.5 중복 판정

AI가 추출한 어휘는 바로 공용 어휘로 저장하지 않고 후보로 처리한다.

1. 태국어 표기를 검색용 형식으로 정규화한다.
2. 같은 정규화 표기의 기존 어휘를 찾는다.
3. 기존 어휘가 없으면 신규 어휘 후보를 만든다.
4. 기존 어휘가 있고 뜻도 같으면 기존 뜻을 재사용한다.
5. 기존 어휘가 있지만 뜻이 다르면 기존 어휘 아래에 뜻 후보를 추가한다.
6. 철자가 비슷하지만 정확히 같지 않으면 자동 병합하지 않고 중복 의심으로 분류한다.
7. 동시에 같은 어휘를 추가해도 최종 저장 단계에서 중복을 차단한다.

정확한 검색·인덱스·동시성 처리 기술은 인프라·ERD 단계에서 결정한다.

### 6.6 병합과 삭제

- 게시된 어휘는 참조 무결성과 학습 기록 보존을 위해 즉시 물리 삭제하지 않는다.
- 중복 병합 시 문제 토큰, 예문, 단어장 등 기존 참조를 대표 어휘로 이동한다.
- 병합 전후 관계와 변경자는 감사 기록에 남긴다.
- 아직 게시되지 않은 생성 후보는 검수 과정에서 폐기할 수 있다.
- 원본 PDF·이미지·텍스트를 별도 자료 엔티티로 보관하는 기능은 만들지 않는다.

## 7. 문장과 태국어 토큰

### 7.1 원문 보존

- AI가 생성하거나 추출한 태국어 원문을 보존한다.
- 화면 표시를 위해 토큰으로 나누더라도 원문 문자열을 다시 조합해 복원할 수 있어야 한다.
- 토큰 순서, 원문 위치, 공백·문장부호 정보를 유지한다.

### 7.2 토큰 출현

같은 어휘가 여러 문제와 문장에 반복될 수 있으므로 문장 안의 각 출현을 별도 기록으로 취급한다.

각 토큰 출현은 다음 정보를 가진다.

- 연결된 공용 어휘와 문맥상 뜻
- 문장 안 순서와 원문 위치
- 화면에 표시할 원형
- 문제 생성에서의 어휘 역할
- 다단어 표현 범위 포함 여부

### 7.3 문장 정보

각 문장은 다음 정보를 사전에 저장한다.

- 태국어 원문
- 한국어 해석
- 문장 전체 한국어 발음
- 문장 전체 성조 기호
- 문장 음성
- 문장 내 토큰 출현 목록
- 문제 또는 개념 콘텐츠 버전과의 연결

## 8. 문제 도메인

### 8.1 초기 문제 범위

초기에는 읽기와 듣기 문제만 제공한다. [`docs/flex-problem-type.md`](../../flex-problem-type.md)의 큰 분류를 기준으로 세부 유형을 관리한다.

듣기 큰 분류:

- 반응 테스트
- 대화문
- 설명문

읽기 큰 분류:

- 어휘·문법
- 동의·유의 관계
- 비문 찾기
- 지문 독해

이 일곱 개는 큰 분류이며, 실제 콘텐츠 구조와 출제 규칙은 세부 유형으로 정의한다.

### 8.2 문제 유형과 버전

- 개발자는 지원 가능한 문제 구조 템플릿을 구현한다.
- 관리자는 서비스 안에서 세부 유형의 이름, 큰 분류, 구조 템플릿, 출제 규칙, 난이도 기준, 승인 예시를 설정한다.
- 세부 유형마다 승인된 예시 문제를 최소 한 개 둔다.
- 기존 템플릿으로 표현할 수 없는 새로운 상호작용은 프론트·백엔드 코드 추가가 필요하다.
- 유형 규칙을 변경하면 새 유형 버전을 만든다.
- 기존 문제 버전은 생성 당시 유형 버전을 계속 참조한다.

### 8.3 문제와 문제 버전

- 문제의 논리적 정체성과 실제 출제 내용을 분리한다.
- 게시된 문제를 수정하면 기존 버전을 덮어쓰지 않고 새 문제 버전을 만든다.
- 사용자의 풀이 기록은 실제로 푼 문제 버전을 참조한다.
- 오답 수정이나 비공개 처리 후에도 과거 풀이 기록의 원문은 추적할 수 있어야 한다.

### 8.4 문제 블록

문제 버전은 순서가 있는 블록으로 구성한다.

- `INSTRUCTION`: 문제 설명
- `PASSAGE`: 읽기 지문 또는 듣기 설명문 대본
- `DIALOGUE`: 화자별 대화
- `QUESTION`: 질문
- `OPTION`: 선택지
- `EXPLANATION`: 정답 해설

모든 블록 안의 태국어는 문장과 토큰 단위로 분석되고 공용 어휘와 연결된다.

### 8.5 표준 문제 설명

- 같은 세부 유형에서 반복되는 태국어 문제 설명은 유형 버전의 표준 설명을 재사용한다.
- 표준 설명도 태국어 토큰, 문장 주석, 음성을 가진다.
- 문제 설명에 반복되는 어휘는 문제 핵심 어휘 빈도와 분리한다.

### 8.6 문제 생성 어휘 역할

문장 안 어휘 출현에는 다음 역할을 부여할 수 있다.

- `TARGET`: 학습·출제의 핵심 어휘
- `REQUIRED`: 관리자가 반드시 포함하도록 고정한 어휘
- `SUPPORTING`: 문장 구성을 위해 사용한 보조 어휘
- `INSTRUCTION`: 반복되는 문제 설명 어휘

같은 공용 어휘라도 출현 위치에 따라 다른 역할을 가질 수 있다.

- 문제 유사도와 어휘 사용 빈도를 계산할 때 `INSTRUCTION`은 별도로 집계하고 영향도를 낮추거나 제외한다.
- 핵심 어휘는 검증된 공용 어휘를 사용한다.
- 보조 어휘에서 신규 후보가 나올 수 있지만 검증·음성 준비 전에는 문제를 게시하지 않는다.
- 관리자는 필수 어휘와 제외 어휘를 고정할 수 있고, 나머지 조합은 AI가 채운다.

### 8.7 난이도와 분류

- 초기 난이도는 쉬움, 보통, 어려움으로 구분한다.
- 난이도 판단 기준은 세부 유형 버전별로 설정한다.
- AI가 난이도를 제안하고 검증 단계에서 규칙과 맞는지 확인한다.
- 문제에는 큰 유형, 세부 유형, 난이도, 주제, 태그를 연결한다.
- 정확한 초기 태그 목록과 추천 가중치는 콘텐츠 설정 단계에서 정한다.

### 8.8 정답과 해설

- 사용자의 첫 제출 답안을 정답률과 오답 판단의 기준으로 저장한다.
- 첫 제출 직후 정답 여부와 해설을 표시한다.
- 해설은 선택지 아래에 인라인으로 표시하는 구성을 기본으로 한다.
- 해설은 한국어 설명을 중심으로 하되 포함된 태국어는 동일한 단어·문장 상호작용을 제공한다.
- 사용자는 같은 문제를 다시 풀 수 있고 재시도 기록은 첫 답안과 분리한다.

### 8.9 유사 문제 방지

- 생성 전에는 같은 유형, 핵심 어휘, 문장 구조가 비슷한 기존 문제를 AI 입력에 제공한다.
- 생성 후에는 어휘 구성, 문장·보기 유사도, 정답 구조를 다시 검사한다.
- 유사하다는 이유만으로 자동 삭제하지 않고 중복 의심으로 표시한다.
- 반복되는 표준 문제 설명은 유사도 판단에서 별도로 처리한다.

## 9. 듣기 문제

### 9.1 기본 표시

- 듣기 콘텐츠도 태국어 원문, 뜻, 한국어 발음, 성조, 토큰, 문장 음성을 모두 사전에 생성한다.
- 최초 화면에서는 듣기 대본의 태국어를 렌더링하지 않는다.
- 흐림 효과로 글자를 숨기지 않고 의미 없는 마스크나 자리 표시자를 사용한다.
- 화자 구조와 재생 컨트롤은 표시한다.

### 9.2 대본 공개

- 사용자는 답을 제출하기 전에도 `대본 보기`를 눌러 전체 대본을 공개할 수 있다.
- 첫 답안을 제출하면 대본을 자동으로 공개한다.
- 공개된 태국어는 읽기 문제와 같은 단어·표현·문장 상호작용을 제공한다.
- 대본 공개 여부는 학습 기록으로 저장하지 않는다.

### 9.3 음성 단위와 화자

- 초기에는 문장별 음성을 제공한다.
- 대화 전체를 자동으로 연속 재생하는 플레이리스트는 초기 범위에서 제외한다.
- 화자 역할은 내레이터, 안내, 화자 A, 화자 B 등을 사용할 수 있다.
- AI가 화자 역할을 제안하고 관리자가 수정할 수 있다.
- 화자 역할과 TTS 음성 프리셋의 연결은 자동화한다.

## 10. 학습자 화면과 기능

### 10.1 전역 내비게이션

초기 상단 내비게이션은 다음 항목으로 구성한다.

- 홈
- 문제
- 단어·표현
- 개념 학습
- 단어 연습

프로필 메뉴에는 이메일, 역할, 관리자·검수 화면 전환, 로그아웃을 둔다. 초기에는 별도 계정 설정 페이지를 만들지 않는다.

### 10.2 인증 화면

- 학교 이메일 입력
- 이메일 전송 완료 안내
- 6자리 코드 입력
- 이메일 로그인 링크 재전송
- 최초 가입과 기존 로그인을 같은 흐름으로 처리

### 10.3 홈

홈은 균형형 대시보드로 구성한다.

- 개인 추천 문제
- 개인 추천 어휘·표현
- 오늘 게시된 문제
- 오늘 게시된 어휘·표현
- 문제, 공용 사전, 내 단어장, 단어 연습으로 가는 빠른 링크

`NEW` 여부는 생성 시간이 아니라 실제 게시 시간을 기준으로 한다. 신규 콘텐츠는 캐러셀 형태로 탐색할 수 있다.

### 10.4 추천

- 초기 추천은 저장된 원시 학습 기록을 사용하는 규칙 기반 방식이다.
- 추천 항목에는 추천 이유를 표시한다.
- 문제 풀이, 첫 오답, 저장, 단어장, 단어 연습 결과를 입력으로 사용할 수 있다.
- 숙련도 점수는 추천 입력으로 사용하지 않는다.
- 숨김·보관·무효 콘텐츠와 비공개 콘텐츠는 추천에서 제외한다.
- 정확한 알고리즘과 가중치는 구현 이후 조정한다.

### 10.5 문제 목록

- 큰 유형과 세부 유형
- 읽기·듣기
- 난이도
- 주제·태그
- 저장한 문제
- 첫 답안 기준 오답 문제
- 최신순 등 정렬
- 페이지 번호 방식 페이지네이션

데스크톱에서는 고정된 왼쪽 필터 영역을 사용하고, 모바일에서는 하단 시트 필터를 사용한다.

### 10.6 문제 상세

- 한 페이지에 문제 하나를 표시한다.
- 읽기 지문은 자연스러운 문단을 유지한다.
- 오른쪽에는 문장 번호 주석 목록을 고정할 수 있다.
- 답 제출 후 선택지 아래에 정답과 해설을 표시한다.
- 문제 저장, 오류 신고, 다시 풀기를 제공한다.
- 관리자에게는 수정, 즉시 숨김, 재검증, TTS 재생성 제어를 추가로 표시한다.
- 관리자가 어휘를 수정할 때 `이 문맥만 수정`과 `공용 어휘 수정` 범위를 선택할 수 있다.

### 10.7 단어·표현

상단 탭은 `공용 사전`과 `내 단어장`으로 구분한다.

공용 사전 검색 대상:

- 태국어 정확 검색
- 태국어 시작·포함 검색
- 한국어 뜻
- 한국어 발음
- 품사, 난이도, 주제, 종류 필터
- 정렬

어휘 상세 정보:

- 태국어 표기
- 뜻 목록
- 한국어 발음과 성조 기호
- 발음별 음성
- 품사·난이도·분류
- 유의어·반의어·관련어
- 이 어휘가 나온 게시 문제
- 예문
- 단어장 추가
- 오류 신고

예문은 유효한 게시 문제 문장을 우선 재사용한다. 적절한 문제 문장이 없으면 AI가 독립 예문을 생성하고 같은 검증 절차를 거친다. 문제 문장을 예문으로 사용할 때 해당 문제 문장 버전과 해석·발음·음성을 함께 재사용한다. 문제가 무효 처리되면 예문에서도 제외하고 대체 예문을 사용한다.

### 10.8 개인 단어장

- 사용자는 여러 단어장을 만들 수 있다.
- 같은 공용 어휘를 여러 개인 단어장에 저장할 수 있다.
- 공용 어휘 데이터를 개인별로 복제하지 않는다.
- 단어장 상세에서 검색, 필터, 페이지네이션을 제공한다.
- 여러 항목을 선택해 다른 단어장에 추가하거나 현재 단어장에서 제거할 수 있다.
- 선택한 단어장으로 단어 연습을 시작할 수 있다.

### 10.9 단어 연습

연습 시작 화면 한 곳에서 다음을 선택한다.

- 출처: 공용 검색 결과 또는 개인 단어장
- 문제 방식
- 문항 수
- 출제 순서

초기 연습 방식:

- 태국어 → 한국어 뜻
- 한국어 뜻 → 태국어
- 음성 → 태국어 또는 한국어 뜻

학습 카드는 전체 뜻·발음·성조·음성을 항상 확인할 수 있다. 사용자는 원하는 시점에 선택형 기억 확인을 시작한다. 답을 제출하면 즉시 전체 정보를 다시 보여준다.

세션과 정답·오답 원시 기록은 저장하지만 숙련도 점수나 단계는 계산하지 않는다. 결과 요약은 세션 종료 시에만 제공한다.

### 10.10 개념 학습

상단 탭은 다음 두 영역으로 구분한다.

- 태국 문자·발음
- 문법

태국 문자·발음 초기 콘텐츠:

- 자음 표
- 고자음·중자음·저자음
- 초성·종성 발음
- 모음
- 성조 부호
- 생음절·사음절
- 성조 결정 규칙
- 자음·모음·받침 조합 예시

문법 초기 콘텐츠:

- 기본 어순
- 부정문과 의문문
- 시제·상 표현
- 기능어
- 분류사

개념 홈은 개념 카드 목록으로 구성하고 상세는 목차, 설명 블록, 규칙 표, 예시 블록을 사용한다. 예시에 포함된 태국어는 공통 단어·문장·음성 상호작용을 제공한다.

초기에는 개념 퀴즈, 진도, 숙련도를 제공하지 않는다. 관리자는 블록 기반으로 초안을 편집하고 검수·게시·버전을 관리한다. 구체적인 교육 내용은 별도로 작성하고 수정할 수 있다.

### 10.11 오류 신고

문제, 어휘, 문장, 개념 콘텐츠에서 같은 오류 신고 창을 사용한다.

자동 첨부 정보:

- 콘텐츠 종류와 ID
- 콘텐츠 버전
- 문제 문장 또는 어휘 뜻
- 음성 ID
- 신고 위치

신고 분류:

- 뜻·해석
- 발음·성조
- 음성
- 정답·해설
- 단어 분할
- 기타

사용자 설명은 선택 입력이다. 신고만으로 콘텐츠를 자동 숨기지 않는다. 초기에는 사용자의 신고 내역 페이지를 제공하지 않는다.

## 11. 학습 기록

### 11.1 저장할 원시 기록

- 문제 풀이: 사용자, 문제 버전, 첫 답·재시도, 선택 답, 정답 여부, 소요 시간, 제출 시각
- 저장한 문제
- 개인 단어장과 단어장 항목
- 단어 연습 세션과 각 답안
- 콘텐츠 오류 신고

### 11.2 첫 답안과 재시도

- 첫 답안을 정답률, 오답 목록, 추천의 기본 기준으로 사용한다.
- 재시도는 학습 이력으로 저장하지만 첫 답안을 덮어쓰지 않는다.
- 사용자는 문제 목록 필터로 저장 문제와 오답 문제를 다시 찾는다.

### 11.3 무효 문제 처리

- 관리자가 이상한 문제를 발견하면 학습 화면에서 즉시 숨길 수 있다.
- 수정은 새 문제 버전으로 만들고 재검증과 필요한 TTS를 거쳐 다시 게시한다.
- 기존 풀이 기록은 보존한다.
- 무효 처리된 문제의 기록은 정답률, 오답 목록, 난이도 판단, 추천 같은 사용자 지표에서 제외한다.

### 11.4 초기 집계 제외

- `user_learning_stats` 같은 집계 테이블을 초기부터 만들지 않는다.
- 숙련도 계산을 위한 별도 테이블·컬럼을 만들지 않는다.
- 미래 통계는 보존된 원시 기록을 기준으로 설계한다.

## 12. AI 콘텐츠 생성

### 12.1 연동 방식

- Claude나 Codex 구독 계정을 서비스 기능으로 공유하지 않는다.
- 서비스 서버가 AI 공급자의 API를 호출한다.
- 학습자 화면에서는 실시간 AI 호출을 사용하지 않는다.
- AI와 TTS 모델·공급자는 인프라 단계에서 정한다.

### 12.2 입력 형식

한 생성 작업에서는 다음 중 하나의 입력 형식만 선택한다.

- `TEXT`: 태국어 또는 한국어가 섞인 텍스트 묶음
- `PDF`: FLEX 대비 교재 등 PDF
- `IMAGE`: 태국어 자료 이미지

같은 형식의 입력은 한 작업에 여러 개 추가할 수 있다. 서로 다른 입력 형식을 한 작업에서 섞지 않는다.

PDF와 이미지는 OCR 텍스트가 없어도 입력할 수 있어야 한다. 페이지 이미지에서 태국어와 한국어를 읽는 실제 방식은 선택한 AI·OCR 공급자에 맞춰 인프라 단계에서 정한다. 현재 예상 자료는 파일당 약 10MB, PDF 약 20페이지 수준이며 정확한 업로드 제한은 인프라 단계에서 확정한다.

입력 자료는 독립적인 자료 관리 엔티티로 운영하지 않는다.

- 자료 관리 메뉴 없음
- 파일·페이지별 처리 상태 없음
- 페이지별 미리보기·요약·추출 결과 없음
- 원본 문서·페이지 출처 추적 없음
- 입력 파일의 임시 보관 기간과 삭제 방식은 인프라 단계에서 결정

### 12.3 생성 목적

관리자는 작업마다 다음 중 하나를 선택한다.

- 어휘만 추출
- 문제만 생성
- 어휘 추출 후 문제 생성

연결 생성은 안전한 자동 진행 방식을 사용한다.

1. 입력에서 어휘 후보를 추출한다.
2. 기존 공용 어휘 중복을 검사한다.
3. 결정 규칙과 독립 AI 검증을 통과한 어휘만 다음 단계에 사용한다.
4. 의심 어휘는 검수 대상으로 분리한다.
5. 통과 어휘를 바탕으로 문제 초안을 자동 생성한다.
6. 어휘와 문제가 게시 조건을 충족할 때까지 후보 상태로 유지한다.

### 12.4 빠른 생성과 고급 설정

빠른 생성의 필수 입력:

- 입력 자료
- 생성 목적
- 프리셋
- 문제 생성 수

고급 설정에서는 다음을 추가로 조정할 수 있다.

- 문제 유형 구성
- 난이도 분포
- 목표 어휘와 제외 어휘
- 신규 보조 어휘 한도
- 문제 유사도 규칙
- 검수 정책
- 화자 역할과 음성 프리셋

관리자는 생성 전에 자동 구성된 프롬프트를 확인할 수 있다. 원본 프롬프트를 직접 편집하는 대신 한국어 추가 지시를 입력한다.

### 12.5 프리셋

프리셋은 반복 생성 설정을 저장한다.

- 읽기·듣기 및 세부 유형 비율
- 난이도 분포
- 목표 어휘 선택 규칙
- 신규 보조 어휘 제한
- 유사 문제 회피 규칙
- 검수 정책
- 듣기 화자 역할

관리자는 짧은 시간에 많은 문제를 만들 때 프리셋과 문제 수만 선택할 수 있다.

### 12.6 문제 생성 프롬프트 조립

문제 생성 요청은 다음 자료를 조합한다.

- 공통 생성 원칙
- 세부 유형 버전의 구조와 출제 규칙
- 세부 유형의 승인 예시 문제 한 개 이상
- 난이도 기준
- 목표·필수·제외 어휘
- 유사한 기존 문제 요약
- 출력 데이터 스키마
- 관리자의 한국어 추가 지시

프롬프트 버전과 실제 사용 모델을 생성 작업 기록에 남긴다.

### 12.7 저작권 원칙

- 입력 자료에서 실제 어휘를 추출해 공용 어휘 후보로 사용할 수 있다.
- 입력 자료의 문제 문장, 해설, 정의, 예문을 그대로 복제해 게시하지 않는다.
- 문제와 해설은 세부 유형 규칙을 따르는 새로운 콘텐츠로 생성한다.
- 입력 자료가 문제 형식 참고에 사용되더라도 승인 예시와 생성 규칙을 통해 신규 문제를 만든다.

## 13. AI 검증과 전문가 검수

### 13.1 검증 원칙

AI 출력은 데이터 스키마 검사, 결정 규칙 검사, 독립 AI 교차 검증을 거친다.

검증 예시:

- 필수 필드 누락
- 태국어 원문과 토큰 위치 불일치
- 정답과 해설 불일치
- 선택지 수와 유형 규칙 불일치
- 목표 어휘 미사용
- 신규 어휘 미검증
- 기존 문제와 높은 유사도
- 필수 문장·단어 음성 누락

관리자는 태국어를 모르므로 검수 화면에는 단순 통과 여부뿐 아니라 경고 이유와 AI 검증 근거를 제공한다.

### 13.2 검수 정책

각 생성 작업 또는 콘텐츠는 다음 정책 중 하나를 사용한다.

- `AI_ONLY`: 독립 AI 검증과 결정 규칙을 통과하면 관리자가 게시 승인 가능
- `AI_PLUS_EXPERT`: AI 검증 후 검수 전문가의 승인이 추가로 필요

두 정책 모두 AI 검증을 생략하지 않는다.

### 13.3 전문가 작업

- 전문가는 할당된 어휘·문제·개념 콘텐츠를 직접 수정할 수 있다.
- 전문가는 승인 또는 반려와 검수 의견을 남긴다.
- 수정 전후 데이터와 승인자를 감사 기록에 남긴다.
- 전문가 수정 후에도 구조 검증과 필요한 TTS 재생성을 수행한다.

## 14. TTS

### 14.1 생성 대상

- 어휘 발음별 음성
- 다단어 표현 음성
- 문제 설명 문장 음성
- 지문·대화·질문·보기 문장 음성
- 개념 학습 태국어 예시 문장 음성

### 14.2 처리 방식

- 콘텐츠 검증을 통과한 뒤 TTS를 생성한다.
- 비동기 일괄 작업으로 처리한다.
- 항목별 대기, 처리 중, 성공, 실패 상태를 관리한다.
- 여러 실패 항목을 선택해 일괄 재시도할 수 있다.
- 개별 항목도 즉시 재시도할 수 있다.
- 기존에 동일한 발음 또는 문장 음성이 있으면 재사용한다.

### 14.3 게시 조건

- 콘텐츠 검증 상태와 TTS 상태를 분리한다.
- 필수 음성이 실패하거나 없으면 게시하지 못한다.
- TTS 공급자 변경이나 재생 오류가 발생하면 해당 음성을 재생성할 수 있다.

## 15. 생성 결과와 게시

### 15.1 생성 작업 상태

생성 작업은 전체 진행 상황과 사용량을 제공한다. 입력 파일·페이지별 세부 처리 화면은 제공하지 않는다.

생성된 어휘와 문제는 항목별로 다음 결과 그룹에 속한다.

- 정상
- 주의 필요
- 생성 실패

한 항목의 실패가 같은 작업의 다른 정상 항목을 막지 않는다.

### 15.2 검수 작업

- 정상 항목은 여러 개를 선택해 일괄 승인할 수 있다.
- 주의 항목은 수정, 재검증, 폐기할 수 있다.
- 실패 항목은 원인을 확인하고 재생성할 수 있다.
- 자동 게시하지 않는다.
- 어휘 승인, 문제 승인, 필수 TTS 준비가 끝난 항목만 최종 게시한다.

### 15.3 생성 기록

콘텐츠에는 원본 문서·페이지 출처 대신 다음 운영 기록을 연결한다.

- 생성 작업
- AI 공급자와 모델
- 프롬프트 버전
- 생성 시각과 실행 관리자
- 검증 결과
- 수정·승인·게시 이력
- 사용량과 예상 비용

## 16. 관리자 센터

### 16.1 접근 방식

- 일반 학습 서비스와 같은 계정을 사용한다.

- 역할이 없는 사용자는 관리자 경로에 접근할 수 없다.

### 16.2 메뉴

- 문제
- 개념 학습

- AI 생성

`자료 관리` 메뉴는 두지 않는다.

### 16.4 어휘 관리

- 어휘·뜻·발음·음성 검색과 필터
- 신규 후보 검수
- 뜻·발음·관계 수정
- 중복 의심 비교
- 대표 어휘 선택과 병합
- 게시·숨김·보관
- 변경 이력 확인

### 16.5 문제 관리

- 유형, 난이도, 상태, 생성 작업, 검수 정책 검색·필터
- 문제 미리 풀기
- 문장·보기·정답·해설 수정
- 문제 버전 비교
- 재검증
- TTS 재생성
- 게시·즉시 숨김
- 유사 문제 경고 확인

관리자는 실제 문제를 풀다가도 이상한 문제나 어휘를 즉시 숨기거나 수정 흐름으로 진입할 수 있다.

### 16.6 오류 신고 처리

- 신고 분류와 대상 콘텐츠 확인
- 자동 첨부된 콘텐츠 버전과 위치 확인
- 처리 상태와 담당자 관리
- 콘텐츠 수정·숨김·재검증으로 이동
- 처리 이력 기록

신고 접수만으로 콘텐츠를 자동 숨기지 않는다.

## 17. 상태와 변경 규칙

### 17.1 상태 축 분리

콘텐츠의 다음 상태를 하나의 값으로 합치지 않는다.

- 생성 작업 진행 상태
- 콘텐츠 검증 상태
- 전문가 검수 상태
- TTS 상태
- 게시 상태

예를 들어 AI 검증은 통과했지만 TTS가 실패한 문제를 정확히 표현할 수 있어야 한다.

### 17.2 게시 콘텐츠 변경

- 게시 전 후보는 직접 수정하거나 폐기할 수 있다.
- 게시된 문제의 내용 수정은 새 버전을 만든다.
- 게시된 문제를 즉시 숨겨도 기존 풀이 기록은 보존한다.
- 게시된 어휘 병합은 참조 이동과 감사 기록을 동반한다.
- 숨김·무효 콘텐츠는 검색, 추천, 신규 풀이에서 제외한다.

- 오류 신고

### 19.5 콘텐츠 운영

- 생성 후보와 검증 결과

- TTS 작업
- 게시 상태
- 감사 기록

원본 PDF·이미지·텍스트를 장기 관리하는 자료 도메인은 만들지 않는다.

## 21. 핵심 수용 시나리오

### 21.1 단어 피드백

사용자가 문제의 태국어 단어를 호버하면 문맥상 뜻·한국어 발음·성조 기호를 확인하고, 클릭하면 저장된 단어 음성을 들을 수 있다.

### 21.2 문장 피드백

사용자가 문장 번호를 호버하면 문장 전체 해석·한국어 발음·성조 기호를 확인하고, 클릭하면 문장 음성을 들을 수 있다.

### 21.3 듣기 풀이

사용자는 처음에 대본을 보지 않고 문장 음성을 재생해 문제를 푼다. 원하면 제출 전 대본을 공개할 수 있고, 첫 답 제출 후에는 대본이 자동 공개된다.

### 21.4 다의어 중복 방지

AI가 기존과 같은 태국어 표기의 다른 뜻을 추출하면 새 어휘를 만들지 않고 기존 어휘에 뜻 후보를 추가한다.

### 21.5 연결 생성

관리자가 같은 형식의 PDF 여러 개와 프리셋, 문제 수를 선택해 `어휘 추출 후 문제 생성`을 실행하면 중복 검사와 AI 검증을 통과한 어휘로 문제 초안이 자동 생성된다. 의심 어휘와 실패 문제는 별도 검수 대상으로 남는다.

### 21.6 게시 차단

문제 내용이 승인됐더라도 필수 문장 음성이 실패하면 게시할 수 없다. TTS 재시도에 성공한 후 관리자가 게시한다.

### 21.7 잘못된 문제 수정

관리자가 문제를 풀다가 오류를 발견하면 즉시 숨긴다. 수정된 새 버전은 재검증과 TTS 준비 후 게시되며 기존 사용자 풀이 기록은 보존되지만 통계·추천 계산에서는 제외된다.

### 21.8 개인 단어장

사용자는 같은 공용 어휘를 여러 단어장에 저장하고, 단어장 일부를 선택해 단어 연습을 시작할 수 있다. 공용 어휘 정보는 사용자별로 복제되지 않는다.

## 22. 검증 전략 원칙

- 데이터 정규화, 중복 판정, 상태 전이, 문제 검증 규칙은 단위 테스트로 검증한다.
- 프론트엔드 핵심 상호작용은 Vitest 컴포넌트 테스트로 검증한다.
- 테스트 설명은 한국어로 작성한다.
- lint, typecheck, build를 구현 단계의 기본 검증으로 사용한다.
- 프로젝트 지침에 따라 E2E 테스트와 E2E 스캐폴딩은 추가하지 않는다.

## 24. 후속 브레인스토밍 세션 경계

각 후속 단계는 별도 세션에서 새 브레인스토밍으로 진행한다. 현재 문서가 후속 세션의 입력이 되지만, 현재 세션에서 인프라·백엔드·프론트엔드 결정을 미리 확정하지 않는다.

### 24.1 인프라 설계와 프로젝트 아키텍처 세션

- 이 통합 기능 기획 문서를 입력으로 사용한다.
- DB·ORM, 검색, 파일·음성 저장소, 비동기 작업, 인증 기반, AI·TTS 연동, 배포 구조를 비교하고 결정한다.
- 프로젝트 전체의 애플리케이션 경계와 공통 아키텍처를 정한다.
- 승인된 결과를 별도의 인프라·프로젝트 아키텍처 문서로 작성한다.

### 24.2 백엔드 구현 계획 세션

- 통합 기능 기획과 승인된 인프라·프로젝트 아키텍처 문서를 입력으로 사용한다.
- ERD, NestJS 모듈 경계, API 계약, 상태 전이, 비동기 작업, 테스트와 구현 순서를 구체화한다.
- 승인된 결과를 별도의 백엔드 구현 계획 문서로 작성한다.
- 이 세션에서는 프론트엔드 구현 계획을 미리 확정하지 않는다.

### 24.3 프론트엔드 구현 계획 세션

- 통합 기능 기획, 인프라·프로젝트 아키텍처, 백엔드 구현 계획과 API 계약을 입력으로 사용한다.
- 페이지, 라우팅, 공통 태국어 상호작용, 컴포넌트 경계, 서버 상태, 반응형 동작, 테스트와 구현 순서를 구체화한다.
- 승인된 결과를 별도의 프론트엔드 구현 계획 문서로 작성한다.

각 세션은 설계 대화, 대안 비교, 사용자 승인, 문서화까지 독립적으로 완료한다. 실제 개발 실행은 이 세션들의 기획 문서와 동일한 작업으로 취급하지 않는다.
