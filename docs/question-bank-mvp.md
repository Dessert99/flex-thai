# 단어 중심 문제 은행 MVP

단어 데이터를 재사용해 암기와 문제 생성을 확장한다. 듣기 문제는 MVP에 포함하지 않으며, 문제의 태국어는 확장 프로그램으로 선택·번역할 수 있는 일반 텍스트로 표시한다.

| 저장 위치 | 역할 |
| --- | --- |
| `vocabularies` | 공용 어휘와 중요도 `importanceWeight`(1~10, 기본 5) |
| `vocabulary_meanings` | 어휘별 뜻, 품사, 난이도, 발음·성조 |
| `questions` | 현재 문제의 본문·질문·보기 JSON·정답·해설·분류·공개 상태·버전·수정 시각 |
| `question_vocabularies` | 문제와 어휘 연결, 선택적인 뜻, 출제 대상/문맥 역할, 등장 횟수 |
| `question_attempts` | 사용자별 매 제출의 답, 채점 결과, 문제 버전, 당시 문제 전체 스냅샷 |

사용자 단어장과 암기 기록은 공용 어휘를 계속 참조한다. 문제 내용은 문장·블록·보기·문제 버전 테이블로 나누지 않는다. 개념 설명의 예문은 기존 문장 구조를 사용하므로 문장 테이블 자체는 남아 있다.

## 중요도와 사용 빈도

중요도는 관리자가 게시된 단어에서도 수정할 수 있다. 빈도는 **현재 게시된 문제**의 연결 행에서 계산하며, 단어 행에 중복된 카운터를 저장하지 않는다.

- `questionCount`: 이 단어가 연결된 문제 수.
- `targetQuestionCount`: 출제 대상(`TARGET`)으로 연결된 문제 수.
- `occurrenceCount`: 연결 행의 등장 횟수 합계.

문제 수정·숨김·게시 때 통계도 함께 달라진다. 한 문제에서 같은 단어가 3번 나왔다면 문제 수는 1, 등장 횟수는 3이다. 관리자 편집에서는 연결 어휘와 횟수를 함께 관리한다. 태국어 문자열을 임의로 분리해서 자동으로 횟수를 추측하지 않는다.

AI 생성의 기본 우선순위는 `importanceWeight / (1 + targetQuestionCount)`다. 한 묶음 내에서 이미 선정한 횟수도 분모에 반영한다. 기본은 문항당 1개이며 프리셋의 `wordsPerQuestion`으로 조절한다. 명시적인 출제 어휘를 지정하면 그 선택을 우선한다. 계산은 도메인의 `vocabulary-selection.ts`에 분리되어 추후 공식을 바꿀 수 있다.

기존 AI·가져오기 입력 형식은 호환을 위해 유지하고, 저장 시 현재 문제와 어휘 연결로 변환한다. 이 입력에서는 토큰·표현의 어휘 정보로 등장 횟수를 집계한다.

## 문제 수정과 풀이

일반 수정은 `requiresRetry=true`로 버전을 올린다. 단순 오탈자 수정은 관리자가 체크를 해제해 버전을 유지할 수 있다. 정답 보기 ID 변경은 반드시 버전을 올린다. 모든 수정은 수정 시각을 갱신하고, 이전 화면의 버전·수정 시각이 맞지 않으면 덮어쓰기를 거부한다.

과거 풀이를 삭제하거나 재채점하지 않는다. 저장된 스냅샷에는 당시 본문·보기·정답·해설과 수정 시각이 포함된다. 마지막 풀이 버전이 현재와 다르면 `UPDATED`, 같으면 그 풀이 결과에 따라 정답/오답 상태를 표시한다. 새로운 버전을 풀면 최신 결과로 바뀐다. 제출 전 버전이 바뀐 경우에는 제출을 거부하고 다시 문제를 열도록 한다. 같은 제출 ID의 재시도는 최초 저장 결과를 돌려준다.

## 데이터 이전

`0019`(뜻·발음 통합) 이후 `0020_question_bank_mvp.sql`을 순서대로 적용한다. 0020은 현재 게시 버전(없으면 최신 버전)을 `questions`로 옮기고, 과거 풀이에는 해당 버전의 스냅샷을 채운다. 모든 기존 문제 버전의 원본 구조는 `migration_archive.question_graphs_0020`에 보관한다. 보관본은 앱의 편집 이력 API로 노출하지 않는다.

이 변경 작업에서는 마이그레이션 파일과 로컬 시드를 수정했으며 실제 DB 적용은 수행하지 않았다. 데이터 이전 SQL의 실 DB 실행 검증도 수행하지 않았다. 코드와 DB 구조를 함께 전환해야 새 조회·수정 코드가 동작한다.
